WORK BRAIN / PLAIN ENGLISH

Five jobs. One clearer way to work.

Think in five places: what just arrived, what is active, what happened, what is reusable, and how to find it. This section is the strategy and checks on sample content, not a live memory source.

AVAILABILITY / EMPLOYER CONTROL

The strategy is available. Runtime is not active.

Local work-memory registration is recorded for the explicit-local profile. Runtime remains disabled, no live records are published, and T2–T6 remain inactive.

AVAILABLE NOW

Strategy + checks on sample content

Read the five-job model and run checks on sample content. This atlas does not publish live records.

VIEW ONLY

Navigation-only Obsidian posture

Obsidian may point to approved source files. It is not the source, writer, or required runtime.

REQUIRES APPROVAL

Live source + writer activation

Current remains a model until a live source, writer, retention rules, and activation gate are approved.

START WITH THE QUESTION

Choose the job that matches what you need to do.

  • Something arrived → Capture
  • I need to act → Current
  • I need the reason → History
  • I need to reuse it → Knowledge
  • I need to find it → Recall
  • I need to see the movement → Loop
  • I need the infrastructure boundary → Context Engine
  • I need to verify it → View contract
01
CAPTURE

What just arrived?

New material lands here before it earns trust.

Stores: evidence, proposals, observations, and inputs to review.

Rule: not authority yet.

02
CURRENT

What needs attention now?

Active work has a place in the model; live Current requires approval.

Stores: open work, next actions, and active decisions.

Rule: mutable working state.

03
HISTORY

What happened, and why?

Durable context keeps the source trail intact.

Stores: source-backed decisions and change context.

Rule: not a complete archive.

KNOWLEDGE

What should we reuse?

Useful understanding stays curated and current.

Stores: working guidance and reference material.

Rule: cite History; do not duplicate it.

05
RECALL

How do I find it?

Search and views make the other jobs easier to use.

Stores: indexes, links, and generated navigation.

Rule: no original content of its own.

SAME MODEL / THREE READERS

Change the emphasis, not the names.

Executives need the boundary. Practitioners need the next move. Implementers need ownership and evidence.

EXECUTIVE

A filing discipline for design work.

The strategy maps new material to Capture, active work to Current, decisions to History, reusable understanding to Knowledge, and retrieval to Recall. It is not a live record system yet.

PRACTITIONER

Five jobs, one rule each.

Use the model to decide where work belongs: what arrived, what is active, what happened, what to reuse, and how to find it. Live Current needs approval first.

IMPLEMENTER

Four stores plus one optional derived plane.

Use sample content to verify the contracts and keep Obsidian view-only. A Context Engine may derive bounded context from approved Knowledge; it does not become a sixth job or a live writer here.

FUNCTIONAL LOOP / IMPROVE

Keep the work useful as it changes.

The jobs are the nouns. Review and Route are transitions, not jobs. Improve is the loop: check the source, route the material, make it findable, and correct what changed.

  1. 01 JOB

    Capture

    New evidence or a proposal enters with its source and purpose visible.

  2. 02 TRANSITION

    Review

    A person checks the source, classification, usefulness, and fit.

  3. 03 TRANSITION

    Route

    Route sends reviewed material into Current, History, or Knowledge: active work to Current, decisions to History, and reusable guidance to Knowledge.

  4. 04 JOB

    Recall

    Indexes, text search, and views help the next task find what matters.

  5. 05 LOOP LOOP BACK

    Improve

    Correct, close, retire, or promote material when context changes.

Improve, explicitly means clearer records and faster orientation. It does not mean silent collection.

OPTIONAL DERIVED PLANE / NOT CONNECTED HERE

Context Engine can sit beside the five jobs.

It can turn approved Knowledge into bounded context for an agent or another consumer. It is infrastructure, not another job, and this atlas does not connect to a live engine.

  1. 01 SOURCE

    Ingest approved sources

    Select allowed material and keep its identity, classification, and source trail visible.

  2. 02 ADMIN

    Shape and validate

    Define the domain, package, notes, lenses, relations, and lifecycle checks.

  3. 03 DERIVED

    Build context

    Create a bounded representation that can be indexed or queried. The storage choice is not settled here.

  4. 04 DELIVERY

    Retrieve for a consumer

    Return a result with source, status, and failure behavior so the reader can verify it.

Boundary: this atlas makes no graph, vector, relational, or other runtime commitment. Obsidian remains navigation-only, and unverified integrations are outside this public contract.

RECALL / SOURCE / VIEW

Recall helps you look; it does not own the record.

SOURCE STORES

Four jobs own content

The model assigns records to Capture, Current, History, and Knowledge. This atlas explains those roles; it does not publish the records.

RECALL VIEW

Generated and disposable

Indexes, links, and views can be rebuilt. If a view disappears, the underlying Markdown still works.

OBSIDIAN FIT

Optional navigation layer

Obsidian may help someone browse the records, but it is not the write path, authority, or required runtime.

RECALL NAVIGATION / VIEW CONTRACT

Use the view to choose. Use the source to trust.

This atlas is a Recall view: it helps you choose and verify; the source files remain authoritative. Obsidian or another Recall view may make the work easier to browse, but it should always show where a record belongs, how much to trust it, and where to verify it.

01 / ORIENT

Where does this belong?

Show the job label and question so a reader knows whether to look in Capture, Current, History, or Knowledge. Recall helps find across them.

02 / VERIFY

Can I trust this?

Keep the record states proposed, active, durable, curated, and derived visible. They are not T1-T6 maturity levels. Never make color or graph position carry the meaning alone.

03 / RETURN

Where is the source?

Link back to the canonical record and its source trail. A view can disappear without taking the record with it.

Fallback: readable Markdown, links, and grep-first retrieval remain usable without Obsidian, a plugin, or a vault configuration.

GOVERNANCE / T1–T6

Governance sits beneath the jobs.

The tiers answer what controls are in place before a capability operates. T1 is specified for explicit local use but not published here; T2–T6 are inactive and off unless approved. They are not the reader's starting point.
