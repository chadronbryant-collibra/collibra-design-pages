# Keep brand guidance current

Use the bundled contracts for relevant Collibra work without requiring the
user to name a skill. Follow a more specific user brief or approved team
format when supplied. For People Solutions colleagues, write as a helpful
colleague: answer first, plain words, only the context needed to act. Keep
conditions beside the step they affect. Remove repeated setup checks and
process commentary from the reader’s artifact.

## Before using brand sources

Check the last successful source review. If it is missing, in the future,
or 60 days old or older, refresh before relying on the guidance as current.
A package version, installation date or a file’s modified time alone does
not establish a successful source review. This is an on-use check, not a
background schedule.

1. Use the user’s connected work Google Drive account. Confirm its identity.
2. Open the verified official source links below first. For slides, also check
   the native template and presentation best practices. For People Solutions
   writing, include the People team voice guide. Reuse these stable file/folder
   IDs on later reviews. If a link has moved, use an existing private binding
   or exact-title search and confirm the authoritative replacement. Never guess
   an ID or choose the newest matching filename as authority by itself.
3. Read current metadata and the relevant content. For toolkit folders, list
   the current assets, then fetch only what the task needs. Compare the
   source revision and rules with the bundled guidance. Keep source documents,
   licensed fonts, non-published private identifiers and downloaded assets private.
4. Keep a local or task-scoped review record: source ID/link, revision or
   modified time, review date, rules checked, changes found and unresolved
   conflicts. Set the successful review date only after the relevant source
   content was actually checked. Persist a record only in an authorized
   private destination; no implicit memory capture or public upload.
5. Apply confirmed current rules to this task. Source changes that affect the
   reusable suite need a reviewed canonical-source update and package release;
   do not silently modify installed caches. An asset link grants no new
   redistribution rights.

If Drive or the source is unavailable, keep working with the bundled snapshot
where safe. Tell the user briefly that its freshness could not be checked and
ask for the specific current source only when the task depends on it. Do not
claim a refresh, invent rules or change the successful-review date.
